# Searching
Source: https://developer.apple.com/design/human-interface-guidelines/searching

## In one line
Put search where people expect it, make it clear what is being searched, and help people type less.

## Rules
1. People expect to search an app with a search field. [Introduction]
2. Let people narrow a search or filter results by attributes (like date, size, type) when that helps, using scope bars and tokens. [Introduction]
3. Let people find text within an open document or page. [Introduction]
4. If search matters, give it a main place in the app: in the toolbar next to other key actions, or as its own tab in a tab-bar app. [Best practices]
5. Aim for one clearly marked place that can find anything in the app. Apps with distinct sections can also offer a local search that filters the current view. [Best practices]
6. Always show what is being searched, with descriptive placeholder text, a scope bar or tokens, or a title (Mail always shows which mailbox you are searching). [Best practices]
7. Offer suggestions: show recent searches before people type and predictive suggestions while they type. [Best practices]
8. Think about privacy before showing search history where others could see it, and if you show it, give people a way to clear it. [Best practices]

## How it applies to a web app on iPhone and Mac
- Have one search that can find tasks, Projects, sessions and so on from anywhere (a command palette on Mac, a search button in the top bar on iPhone); table filters on each page are the local search.
- Placeholder text names what is searched ("Search tasks in Omicron"), and active filters show as removable chips.
- Show recent searches when the field is focused and empty, with a "Clear" option.
- The browser's own Find (Command-F) already covers find-in-page; don't block it.
